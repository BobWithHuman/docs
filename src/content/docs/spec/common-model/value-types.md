## 가져온 값과 새로 쓴 값

Call Parser는 호출을 요소로 나누면서 값을 둘로 가른다. 어딘가에서 가져온 값과, 메일 본문이나 코드처럼 에이전트가 새로 쓴 값이다. 새로 쓴 값은 따지지 않는다. (확정)

둘을 가르는 기준은 정하지 않았다. (미정)

## 가져온 값의 확인

행동은 사용자가 시켰더라도 호출에 들어간 값은 바꿔치기될 수 있다. 그래서 가져온 값은 시작점과 별개로 하나씩 확인한다. 값이 글자 그대로 어디에 있었는지는 Token Index가 찾고, 확인은 Provenance Tracer가 한다. (확정)

| 값이 있던 곳 | 확인 | 결과 | 상태 |
|---|---|---|---|
| 요청에 글자 그대로 있음 | 묻지 않는다 | 괜찮은 값 | 확정 |
| 문단에서 옴 | Jev: `"값" is something the user referred to in "요청"` | 예면 괜찮은 값, 아니오면 끼워 넣은 값 | 확정 |
| 어디에도 글자 그대로 없음 | Jev: `"값" is taken from this output` | 예면 괜찮은 값, 아니오면 근거 없는 값 | 확정 |

Jev 질문의 문구는 초안이다. (초안)

끼워 넣은 값이 하나라도 있으면 시작점과 상관없이 차단한다. 근거 없는 값은 세션이 CLEAN이면 통과, EXPOSED면 사용자에게 묻는다. 결과에서 계산된 값의 근거 확인은 평가 전 범위에서 빠져 있다. (확정)

## 정규화

값을 찾고 비교하기 전에 엔진에 들어오는 모든 입력에 같은 규칙으로 정규화를 적용한다. 정규화한 것과 별도로 원본도 함께 보관한다. (초안)

| 대상 | 규칙 | 상태 |
|---|---|---|
| 줄바꿈 | `\r\n`과 `\r`을 `\n`으로 바꾼다. | 초안 |
| 경로 | 작업 디렉터리 기준 상대 경로로 바꾸고, 구분자는 `/`로 맞추고, `./`를 없앤다. | 초안 |
| URL | scheme과 host를 소문자로 바꾸고 끝의 `/`를 없앤다. | 초안 |
| 공백 | 앞뒤 공백을 없애고 이어진 공백은 하나로 줄인다. | 초안 |
| 유니코드 | NFKC로 정규화하고 폭 0 문자를 없앤다. | 초안 |

## 미정

가져온 값과 새로 쓴 값을 가르는 기준, Element의 역할 이름 목록이 없다. 정규화에서는 어떤 값을 경로나 URL로 볼지, 규칙을 어떤 순서로 적용할지를 정하지 않았다. Token Index의 조각 일치가 어느 정도 길이의 조각부터 일치로 볼지도 남아 있다.
