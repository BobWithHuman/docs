Provenance Record에는 호출 하나에 대해 인과 구조 파악 계층이 알아낸 내용이 모두 담깁니다. Provenance Tracer가 PreToolUse 처리의 마지막 단계에서 만들어 Decision Module로 넘깁니다. Decision Module은 Jev 없이 이 기록만 보고 판정합니다.

## 필드

모든 필드는 Provenance Tracer가 채웁니다.

| 필드 | 담는 내용 |
|---|---|
| 호출·요소 | 호출과 그 요소(역할, 값). Call Parser가 나눈 요소와 Token Index가 찾은 값의 출처가 들어갑니다. |
| 할 일과 수행 점수 | 호출이 수행하는 할 일과, 호출이 그 할 일을 정말 수행하는지 Jev가 답한 점수 |
| 사슬 | 호출에서 시작점까지 따라 올라간 간선 |
| 시작점 | USER, DELEGATED, DOC, ERROR, SELF, UNRESOLVED 중 하나 |
| 함께 걸린 후보 | 기준 점수를 넘었지만 따라가지 않은 후보와 그 점수 |
| 사슬의 최솟값 | 아직 정의하지 않았습니다. 아래 "미정"을 보세요. |
| 세션 상태 | CLEAN 또는 EXPOSED |
| 판단 못 한 이유 | 판단하지 못했을 때 그 이유 |

## 시작점

호출에서 제어 의존 간선을 따라 올라가다 멈춘 곳이 시작점입니다. 올라가는 규칙은 [Provenance Tracer](/docs/spec/causal-layer/provenance-tracer/#시작점-규칙)에 있습니다.

| 시작점 | 해당하는 곳 |
|---|---|
| USER | 사용자 요청, 사용자 자신의 설정 파일 |
| DELEGATED | 맡긴 문서의 주제 부분, 붙여 넣은 글의 주제, 저장소 지침 파일 |
| DOC | 그 밖에 읽은 모든 글. 맡긴 문서라도 주제 밖의 문단은 DOC입니다. |
| ERROR | 도구가 돌려준 오류 메시지 |
| SELF | 판단은 했지만 어디에도 이어지지 않음. 어느 후보도 기준 점수를 넘지 못한 경우입니다. |
| UNRESOLVED | Jev 응답을 받지 못해 판단하지 못함 |

### DELEGATED와 DOC

사용자가 "#12 원인 정리해 줘"라고 하면, 해결할 문제는 이슈 본문에 적혀 있습니다. 그래서 맡긴 문서의 주제까지는 사용자가 준 일로 봅니다.

이를 위해 사용자가 요청에서 가리킨 문서를 기록해 두고, 그 문서를 읽을 때 출처별 규칙으로 주제를 표시합니다. 주제가 아닌 나머지는 모두 DOC입니다.

DOC라는 이유만으로 막지는 않습니다. 그 글이 할 일을 시켜서 시작점이 됐을 때만 문제가 됩니다.

## 세션 상태

시키는 문장으로 표시된 문단이 세션에 한 번이라도 들어오면 세션은 EXPOSED가 됩니다. 한 번 EXPOSED가 되면 다시 CLEAN으로 돌아가지 않습니다.

EXPOSED가 되면 두 가지만 바뀝니다.

- 이후 들어오는 할 일부터 시키는 문단이 부모 후보에 들어갑니다.
- 판단이 막힌 경우의 기본 판정이 통과에서 묻기로 바뀝니다.

권한을 줄이거나 도구를 막지는 않습니다.

## 미정

- "사슬의 최솟값"이 무엇의 최솟값인지. 판정 표의 "사슬 확신도"가 이 값을 가리키는지도 함께 정해야 합니다.
- 판정에 필요하지만 필드 목록에 없는 정보를 어디에 담을지. 바깥 영향 판별 결과, 가져온 값마다의 확인 결과, 할 일을 시킨 문단이 숨긴 글인지가 여기에 해당합니다.
- 판단 못 한 이유의 값 목록과 필드별 형식.
