## 하는 일

Token Index는 가져온 값이 앞서 관찰한 요청이나 문단에 그대로 적혀 있는지 찾습니다. Jev는 쓰지 않습니다.

찾는 순서는 세 단계입니다.

1. 값을 통째로 찾습니다.
2. 없으면 정규화한 뒤 다시 찾습니다.
3. 그래도 없으면 조각 단위로 찾습니다.

값이 여러 곳에 있으면 가장 먼저 나온 곳을 출처로 봅니다. 앞서 읽은 문서의 값이 도구 결과를 한 번 거치면서 출처가 세탁되는 것을 막기 위해서입니다.

정규화 규칙은 [Value Types](/docs/spec/common-model/value-types/#정규화)에 있습니다. 이 규칙은 이번 명세에서 정한 초안입니다.

1차에는 통째로 찾기와 정규화 후 찾기까지만 만듭니다.

## 받는 것

| 입력 | 보내는 곳 |
|---|---|
| Element 중 가져온 값 | Call Parser |
| 앞서 관찰한 Request와 Segment의 글 | Collector |

## 내놓는 것

| 출력 | 내용 |
|---|---|
| 노드 | 만들지 않습니다. |
| 간선 | value_from (Element → 값이 적힌 Request나 Segment). 찾지 못하면 만들지 않고, 그 값은 "어디에도 그대로 없음"으로 확인 단계에 넘어갑니다. |
| Provenance Record | 호출·요소 필드에 들어갈 값의 출처 |

## Jev 질문

Token Index는 Jev에 묻지 않습니다.

## 미정

- 조각 단위로 찾을 때 어느 길이부터 일치로 볼지.
- 어떤 값을 경로나 URL로 볼지, 정규화 규칙을 어떤 순서로 적용할지.
