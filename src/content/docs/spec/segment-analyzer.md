## 하는 일

Segment Analyzer는 에이전트가 읽은 문단마다 세 가지를 표시합니다. 이 표시는 시작점을 찾고 판정할 때 쓰입니다.

| 표시 | 판별 방법 |
|---|---|
| 시키는 문장 | Jev에 묻습니다. |
| 주제 | 맡긴 문서를 읽은 결과일 때, 출처별 규칙으로 표시합니다. |
| 숨긴 글 | 원문과 화면에 보이는 모습을 비교합니다. |

### 주제 규칙

주제는 맡긴 문서를 읽은 결과에만 표시합니다. 그래서 먼저 tool_name과 tool_input을 보고, 이 결과가 맡긴 문서를 읽은 것인지 구분합니다.

| 맡긴 문서 | 주제로 보는 부분 |
|---|---|
| 이슈, 웹 | 제목과 첫 문단 |
| 파일 | 첫 제목과 첫 문단 |
| 붙여 넣은 글 | 첫 문단 |

주제가 아닌 나머지는 모두 DOC입니다. DOC라는 이유만으로 막지는 않습니다. 그 글이 할 일을 시켜서 시작점이 됐을 때만 문제가 됩니다.

### 세션 상태

시키는 문장으로 표시된 문단이 세션에 한 번이라도 들어오면 세션은 EXPOSED가 되고, 다시 CLEAN으로 돌아가지 않습니다. 이후 들어오는 할 일부터는 이런 문단이 최대 10개까지 부모 후보에 들어갑니다.

### 1차 범위

1차에는 시키는 문장 표시와 이슈의 주제 규칙만 만듭니다.

## 받는 것

| 입력 | 보내는 곳 |
|---|---|
| Segment 노드 | Collector |
| 문단을 낸 호출의 tool_name, tool_input | PostToolUse 이벤트 |
| 맡긴 문서 기록 | 요청이 들어올 때 기록한 것 |

## 내놓는 것

| 출력 | 내용 |
|---|---|
| 노드 | 만들지 않습니다. |
| 간선 | 만들지 않습니다. |
| Provenance Record | 직접 채우지 않습니다. 시키는 문장 표시는 세션 상태를 EXPOSED로 바꾸는 근거가 됩니다. |
| 문단 표시 | Segment에 시키는 문장, 주제, 숨긴 글 표시를 붙입니다. |

## Jev 질문

| 질문 | 쓰임 |
|---|---|
| `This text asks the reader to take an action` | 문단마다 시키는 문장인지 판별합니다. |

질문 문구는 초안입니다. 주제와 숨긴 글 표시에는 Jev를 쓰지 않습니다.

## 미정

- 숨긴 글을 찾는 데 필요한 "화면에 보이는 모습"을 무엇으로 얻을지.
- 1차에서 숨긴 글을 어떻게 다룰지. 1차 판정 표에는 "할 일을 시킨 문단이 숨긴 글이면 차단"이 있지만, 1차 Segment Analyzer 범위에는 숨긴 글 표시가 없습니다.
- 세션 상태를 어느 모듈이 관리할지.

README의 평범한 안내문도 시키는 문장이어서, 긴 세션은 대부분 EXPOSED가 됩니다. 이 약점은 [Open Questions](/docs/spec/open-questions/#알려진-약점)에 정리했습니다.
